# 알림 & 스케줄

## 1. 시간표

모든 cron은 **UTC** 기준 (GitHub Actions 규칙). KST = UTC+9.

| 워크플로 | cron (UTC) | KST | 하는 일 |
|---|---|---|---|
| `brief-kr.yml` | `30 22 * * 0-4` | **평일 07:30** | 국장 데이터 갱신 + 장전 브리핑 → 텔레그램 |
| `brief-us.yml` | `30 12 * * 1-5` | **평일 21:30** | 미장 데이터 갱신 + 장전 브리핑 → 텔레그램 |
| `data-sync.yml` | `30 7,21 * * 1-5` | 평일 16:30 / 06:30 | 장 마감 후 시세·뉴스·이벤트 전체 재계산 |

### 왜 이 시간인가

```
국장  09:00 개장  ←─ 1시간 30분 전 ─── 07:30 브리핑 발송
                                        (기상 직후 ~ 출근길에 읽기 좋음)

미장  22:30 개장(서머타임) / 23:30(표준시)
                 ←─ 1~2시간 전 ────── 21:30 브리핑 발송
```

> `0-4`(일~목) 22:30 UTC = 월~금 07:30 KST. 요일이 하루 밀리는 점 주의.

### 휴장일 처리

`pipeline/util/holidays.py`가 국장·미장 휴장일을 판정한다.
휴장일이면 **브리핑을 보내지 않는다** (스팸 방지).
판정 근거: 최근 거래일 데이터가 어제/오늘 것인지 + 하드코딩된 공휴일 목록.

## 3. 텔레그램 봇 세팅 (사용자 작업)

1. 텔레그램에서 **@BotFather** 검색 → `/newbot`
2. 봇 이름·아이디 입력 → **토큰** 발급 (`8123456789:AAF...`)
3. 만든 봇과 대화 시작 → 아무 메시지나 전송 (예: `안녕`)
4. 아래 명령으로 `chat_id` 확인:

```bash
python -m pipeline.run telegram-whoami --token 발급받은토큰
```

5. 발급받은 토큰과 chat_id를 시크릿에 등록 → [05-운영가이드.md](05-운영가이드.md)

### 3.1 여러 명에게 보내기

`TELEGRAM_CHAT_ID`에 콤마로 여러 개를 넣으면 전원에게 발송된다.
하나만 넣으면 기존과 완전히 동일하다.

```
TELEGRAM_CHAT_ID=123456789,987654321,-1001234567890
```

- 개인에게 보내려면 **상대가 봇에게 먼저 `/start`를 보내야 한다.** 텔레그램은 봇이 먼저
  DM을 걸지 못하게 막는다. 그 전에는 `telegram-whoami`에 chat_id가 잡히지도 않는다.
- **그룹/채널**은 이 제약이 없다. 봇을 초대하고 아무 메시지나 보낸 뒤 나오는
  음수 chat_id(`-100...`)를 쓴다. 인원이 많으면 이쪽이 관리하기 편하다.
- 발송은 수신자별로 순차 진행하며 사이에 0.5초를 둔다(텔레그램 rate limit 여유).
  수신자가 1명이면 대기 자체가 없다.

자세한 절차는 [05-운영가이드.md](05-운영가이드.md) ④-1.

## 4. 실패 처리

| 상황 | 동작 |
|---|---|
| 데이터 소스 일부 실패 | 경고 로그 남기고 나머지로 브리핑 생성 |
| 모든 가격 소스 실패 | 브리핑 중단, `⚠️ 데이터 수집 실패` 알림만 발송 |
| Gemini 실패/미설정/쿼터초과 | 요약은 규칙기반 폴백(`source: "rule"`), 번역은 원문 유지 |
| 텔레그램 발송 실패 | 3회 재시도(지수 백오프) → 실패 시 Actions 잡 실패 처리 |
| **수신자 일부만 실패** | 나머지 수신자에게는 그대로 발송. 실패한 chat_id를 경고 로그에 남긴다 |
| 휴장일 | 발송 없음, 잡은 성공 종료 |

수신자 추가 시 자주 나오는 텔레그램 응답은 사람 말 힌트로 바꿔서 로그에 남긴다
(`can't initiate conversation` → "상대가 봇에게 먼저 /start 를 보내야 합니다",
`chat not found` → "chat_id가 틀렸습니다", `blocked` → "상대가 봇을 차단했습니다").

> 호출량을 조절한다. 한도 초과 시 자동으로 규칙기반/원문 폴백.
