## 1. 프로젝트 개요

국내(KOSPI/KOSDAQ)·미국(NYSE/NASDAQ) 시장의 **뉴스와 차트를 연결**해 보여주는 개인용 대시보드 + 매일 장 시작 전 텔레그램 브리핑. 서버·DB 없이 GitHub Actions가 정적 JSON을 생성해 레포에 커밋하고, Vercel에 배포된 React 앱이 그 JSON만 읽는다. 운영비 0원이 설계 제약.

### 1.1 요구사항 대응 (R1~R8)

| # | 요구사항 | 구현 위치 | 상태 |
|---|---|---|---|
| R1 | 국장·미장 뉴스 통합 정리 | `pipeline/collect/news.py` (RSS 20종) → `analyze/score.py`, `analyze/link.py` | ✅ |
| R2 | 주요 뉴스 모바일 전송 | `pipeline/notify/telegram.py` (HTML parse mode) | ✅ |
| R3 | 매일 장전 발송 (국장/미장 각각) | `.github/workflows/brief-kr.yml`, `brief-us.yml` | ✅ |
| R4 | 종목별 차트 데이터 | `collect/prices.py` (FinanceDataReader 2년 일봉) + `analyze/technical.py` (지표 11종 + 차트 분석) | ✅ |
| R5 | ⭐ **차트 등락일 ↔ 그날 뉴스 연동** | `analyze/events.py` → `link.py` → `summarize.py`/`llm.py` → `web/.../TickerChart.tsx` | ✅ |
| R6 | 시장 경제 흐름 정보 | `collect/macro.py` (12종) + 섹터 히트맵 + `analyze/mood.py` | ✅ |
| R7 | 초보 친화 UI/UX | 용어 툴팁 39종, 한국식 색상, 사람말 포맷터, 도움말 차트분석 탭 | ✅ |
| R8 | 유료 사이트 수준 | 종목 검색, 워치리스트, 다크모드, 반응형, 캔들 클릭 상세, **차트 분석 신호** | ✅ |

### 1.2 명시적 비목표

- **개별 종목에 대한 매수/매도 권유·목표가 제시** (투자자문 규제 회피 — 사실 전달만).
  `analysis`가 내놓는 "추격 매수 신호" 같은 문구는 기술적 분석 교과서가 그 차트
  모양에 붙인 **국면 이름을 그대로 옮긴 관찰**이며, 근거(지표 12가지)와 한계
  (후행성·재료 미반영)를 항상 같이 노출한다. 목표가·비중·매매 시점은 제시하지 않는다.
- 실시간 시세 (무료 소스 한계 → 일봉/지연 시세)
- 자동매매 연동
- 로그인·회원 시스템 (단일 사용자, 워치리스트는 localStorage)

## 2. 기술 스택

### 2.1 파이프라인 (Python)

| 항목 | 버전/값 | 역할 |
|---|---|---|
| Python | 3.12 (Actions `setup-python@v5`) | 파이프라인 런타임 |
| `finance-datareader` | >=0.9.96 | 국장·미장·지수·환율·원자재 일봉 + 상장목록. **API 키 불필요** |
| `feedparser` | >=6.0.11 | RSS 파싱 (타임아웃 인자 없어 소켓 전역 타임아웃으로 감쌈) |
| `pandas` | >=2.0 | OHLCV 변환·롤링 통계 |
| `requests` | >=2.31 | Gemini REST 호출 |
| `python-dotenv` | >=1.0.0 | 로컬 `.env` 로드 (Actions에선 실제 env 주입) |
| 표준 라이브러리 | `zoneinfo`, `urllib`, `hashlib`, `html`, `tempfile` 등 | 타임존, 텔레그램 전송, dedup 키, 원자적 쓰기 |

> 외부 SDK 의존성 없음: Gemini는 REST 직접 호출, 텔레그램은 `urllib`.
> `pykrx`는 KRX 로그인 요구로 **사용 불가** 판정 → 의존성에서 제외 (01-데이터소스.md §1).

### 2.2 LLM

| 항목 | 값 |
|---|---|
| 제공자 | Google Gemini (무료 티어) |
| 모델 | `gemini-2.5-flash` (`GEMINI_MODEL` env로 교체 가능) |
| 엔드포인트 | `POST https://generativelanguage.googleapis.com/v1beta/models/{model}:generateContent?key=…` |
| 호출 설정 | `temperature 0.3`, `maxOutputTokens 2048`, `responseMimeType: application/json`, `thinkingConfig.thinkingBudget = 0` |
| 용도 | ① 이벤트 원인 해설(R5) ② 브리핑 3줄 요약 ③ 해외뉴스 번역(기본 OFF) |
| 폴백 | 키 없음/429/4xx/파싱실패 → 규칙 기반 요약, 번역은 원문 유지 |

### 2.3 웹 프론트엔드

| 항목 | 버전 | 비고 |
|---|---|---|
| React | ^19.1.0 | `StrictMode`, 함수 컴포넌트 + hooks만 사용 |
| react-dom | ^19.1.0 | |
| react-router-dom | ^7.6.0 | `BrowserRouter` (SPA, Vercel rewrite 필요) |
| lightweight-charts | ^5.0.7 | TradingView 제작. v5 API (`addSeries(CandlestickSeries, …)`, `createSeriesMarkers`) |
| Vite | ^7.0.0 | dev 서버 포트 5173 고정 |
| TypeScript | ^5.8.0 | `strict`, `noUnusedLocals/Parameters`, `noEmit` (빌드는 `tsc -b && vite build`) |
| Tailwind CSS | ^4.1.0 | `@tailwindcss/vite` 플러그인 + `@import "tailwindcss"` (v4 방식, `tailwind.config` 파일 없음) |
| @vitejs/plugin-react | ^5.0.0 | |

- 상태관리 라이브러리 없음 — React Context(설정) + 자체 `useAsync` 훅 + `localStorage`.
- 아이콘 라이브러리 없음 — 이모지 사용.
- 폰트 로딩 없음 — `Pretendard`가 있으면 쓰고 없으면 시스템 폰트 폴백.

### 2.4 인프라

| 레이어 | 선택 | 설정 |
|---|---|---|
| 배치 실행 | GitHub Actions (ubuntu-latest) | 워크플로 4종, `concurrency: stock-pulse-data`로 상호 배타 |
| 데이터 저장 | **git 레포의 `data/` 디렉터리** | Actions 봇(`stock-pulse-bot`)이 커밋/푸시 |

| 로컬 실행 | `start-web.bat`/`stop-web.bat` + PowerShell 스크립트 | §10 |

## 4. 시스템 아키텍처

### 4.1 전체 흐름

```
┌───────────────── GitHub Actions (cron, UTC) ──────────────────┐
│ data-sync  30 7,21 * * 1-5   장 마감 후 전체 재계산            │
│ pulse      0 */2 * * *       2시간마다 경량 갱신               │
│ brief-kr   19:20~23:20 UTC   40분 간격 7슬롯 → 게이트가 1개 채택│
│ brief-us   08:40~14:00 UTC   40분 간격 9슬롯 → 게이트가 1개 채택│
└───────────────────────────┬───────────────────────────────────┘
                            │ python -m pipeline.run {sync|pulse|brief}
        ┌───────────────────┴────────────────────┐
        ▼                                        ▼
 [collect] FinanceDataReader 일봉·상장목록  [analyze] 이벤트 탐지 → 뉴스 매칭
           RSS 20종 + 종목별 뉴스 + 백필             → 규칙 요약 → 전역 상위 LLM 해설
           매크로 12종                               → importance·감성·분위기
        └───────────────────┬────────────────────┘
                            ▼
                data/**.json  (util/io.py 원자적 쓰기)
                            │
                git add data/ && commit && push   ← 봇 커밋
                 │                              │
                 ▼                              ▼
        [notify] 텔레그램 발송            [web] Vercel 자동 재배포
         → 휴대폰 푸시                     → copy-data → /data/*.json fetch
```

### 4.2 핵심 설계 결정

| 결정 | 이유 |
|---|---|
| **정적 JSON을 git에 커밋** | DB·백엔드 0개. 히스토리는 git이 관리. Vercel은 순수 정적 호스팅 |
| **LLM 예산을 전역(run 단위)으로 관리** | 무료 티어는 분당/일일 한도 → 종목당 배분하면 앞쪽 종목이 다 써버림 |
| **ETF는 뉴스 수집 스킵 티어** | 바스켓은 개별 뉴스로 설명 불가. ETF 1개 0.4초 vs 종목 12.9초 → 68개 추가에도 실행시간 거의 불변 |
| **이벤트 뉴스 윈도 = 직전 종가~당일 종가** | 수요일 상승은 화요일 마감 후 뉴스부터가 원인. 달력 날짜 기준으로는 못 잡음 |
| **경량 pulse 분리** | 전체 sync는 20분+ → 상시 최신 매크로/뉴스는 2시간마다 2분짜리 갱신으로 커버 |
| **한국식 색상 통일(상승=빨강)** | 국내 사용자 기준. 설정에서 미국식 전환 가능 |

  판정·**다음 발송 예정 시각**을 한 화면에. 브리핑은 하루 한 번 개장 직전 몇십 분에만

### 5.3 가격 수집 (`collect/prices.py`)

- `fetch_ohlcv(symbol, years=2, retries=2)` — `fdr.DataReader(symbol, start)`. 실패/빈 프레임이면 `1.0 + attempt`초 대기 후 재시도, 최종 실패 시 경고 로그 + `None`.
- `_normalize()` — 인덱스를 `DatetimeIndex`로, 중복 날짜는 마지막 것만, 정렬. `Open/High/Low/Close/Volume` 중 없는 컬럼은 Close로 채우고 Volume은 0(지수·환율은 거래량이 없다). `Close <= 0`은 데이터 글리치로 제거, 숫자 변환 실패는 NaN → drop.
- `to_rows()` — `[["YYYY-MM-DD", o, h, l, c, v], …]` 배열 압축형. 소수 4자리 반올림, Volume은 int.
- `quote_from()` — 최신봉 + 전일종가·변화·변화율, `volumeVsAvg20`(당일/20일평균), `high52`/`low52`(최근 252봉).
- `spark(df, 30)` — 최근 30 종가 리스트.
- `_fdr()`로 지연 import (모듈 로딩이 느림).

### 5.4 유니버스 메타 (`collect/universe.py`)

- `_kr_meta()` — `StockListing("KOSPI")`, `("KOSDAQ")`으로 시총(`Marcap`)·거래대금(`Amount`)·주식수·거래소, `("KRX-DESC")`로 섹터·산업. 코드는 6자리 zero-fill.
- `_us_meta()` — `StockListing("S&P500")`, `("NASDAQ")`으로 영문명·섹터.
- 두 함수 모두 **24시간 디스크 캐시**(`.cache/meta_kr.json`, `meta_us.json`) — NASDAQ 목록이 ~9초.
- `enrich()` — config 유니버스에 메타 병합. 섹터 결측은 KR `"기타"` / US `"Other"`. 개별 목록 실패는 경고 후 계속.

### 5.5 뉴스 수집 (`collect/news.py`)

**티어 1 — 시장 피드** `fetch_market_feeds(markets)`
- `FEEDS`를 순회, 시장 필터. 예외/빈 응답은 dead로 카운트하고 **계속 진행**.
- `_parse()`가 `socket.setdefaulttimeout(15)`로 감싸고 끝나면 원복 — feedparser에 timeout 인자가 없어서 필요한 우회.
- `_entry_to_item()` — 제목 HTML 정리 + Google 접미사 제거, 6자 미만 제목은 폐기. 요약은 220자 절단. `publishedAt`은 `published_parsed`/`updated_parsed`를 UTC로. `id = sha1(정규화 URL)[:8]`, `_dedup` 키 부착.

**티어 2 — 종목별** `fetch_ticker_news(ticker, limit=25)`
- US: Yahoo 티커 RSS. KR: Google News `"{종목명}" 주가` 검색 + 1.2초 sleep.
- Google News 항목은 `entry.source.title`이 실제 매체명 → `source` 교체. 항목마다 해당 종목을 `score 0.95`로 미리 태깅.

**티어 3 — 과거 이벤트 백필** `fetch_event_news(ticker, event_date, window=2, limit=6)`
- Google News `after:/before:` 연산자로 특정 과거 날짜 구간 뉴스를 가져온다. RSS는 최근 것만 담기 때문에 이것 없이는 몇 달 전 급등락일을 설명할 수 없다.
- KR: `"종목명" after:D-2 before:D+3` / US: `"CompanyEn" stock after:… before:…`

**dedupe** `dedupe(items)`
- 키: 제목 정규화(노이즈 문자 제거·공백 제거·소문자) 후 sha1 앞 16자. 정규화 제목이 12자 미만이면 정규화 URL 해시로 대체.
- 같은 기사면 `sourceWeight` 높은 쪽을 남기고 `dupCount`를 누적(여러 매체가 보도 = 중요 신호로 재사용).
- `score.enrich`가 `_dedup`을 제거하므로, 키가 없으면 title+url로 재계산하는 방어 로직 포함.
- 결과는 `publishedAt` 내림차순.

### 5.7 ⭐ 이벤트 탐지 (`analyze/events.py`)

30봉 미만이면 빈 리스트. 파생 컬럼:

```
ret      = Close.pct_change() * 100
retStd   = ret.rolling(60, min_periods=20).std().shift(1)   # shift → 당일이 자기 기준을 부풀리지 않게
volMa20  = Volume.rolling(20, min_periods=5).mean().shift(1)
gap      = (Open - prevClose) / prevClose * 100
z        = |ret| / retStd            (retStd > 0.3 일 때만, 아니면 0)
volRatio = Volume / volMa20
```

분류(`_classify`, 우선순위 순):

| 조건 | type |
|---|---|
| `|ret| >= 6.0` 또는 `z >= 2.4` | `surge`(ret>0) / `plunge`(ret<0) |
| `volRatio >= 3.5` **및** `|ret| >= 2.0` | `volumeSpike` |
| `|gap| >= 4.0` | `gapUp` / `gapDown` |
| 그 외 | 이벤트 아님 |

severity(`_severity`): 기본 1 → `EVENT_SEVERITY_BANDS`로 상향(≥9% → 2, ≥13% → 3) → `z >= 3.0` 또는 `volRatio >= 4.0`이면 +1 (최대 3).

출력 필드: `id`(`{code}-{YYYY-MM-DD}`), `date`, `type`, `severity`, `changePct`, `zScore`, `volumeRatio`, `gapPct`(|gap|≥0.5일 때만), `close`, `volume`. 날짜 내림차순 후 최근 40건.

`label_for(event)` — 뉴스가 없을 때 쓰는 폴백 라벨("+5.2% 급등", "거래량 급증", "갭 상승 출발" 등).

> 임계값은 실측 튜닝 결과: 느슨한 값으로는 거래일의 ~35%가 이벤트로 잡혀 의미가 없었고, 현재 값은 종목당 연 10~25건 수준.

### 5.8 지표 · ⭐ 차트 분석 (`analyze/technical.py`)

`indicators.py`는 이 모듈의 `series()`를 부르는 얇은 래퍼다. **차트에 그리는 선과 신호 판정이 같은 공식을 써야** 분석 카드가 말하는 근거와 화면에 그려진 선이 어긋나지 않는다.

**(1) `series(df)` — 차트 오버레이용 시계열**

`ma5/ma20/ma60/ma120`(SMA), `rsi14`(Wilder식 EWM, `alpha=1/period`, 결측 50), `volMa20`, `bbUpper/bbLower`(20일 SMA ±2σ), `macd/macdSignal/macdHist`(12/26 EMA 차이, 시그널 9 EMA). 모두 **`ohlcv.rows`와 같은 길이·순서**이고 결측은 `null`. RSI 소수 1자리, volMa20 정수, MACD 3자리(원화 종목이면 수백, 미국 저가주면 0.0x라 자릿수를 넉넉히), 나머지 2자리.

**(2) `analyze(df)` — 마지막 봉 기준 종합 판정** (스키마 §4 `analysis`)

기법 12가지를 각각 `bullish|bearish|neutral` + `strength`(0~1) + `weight`(1~3)로 판정한다.

| key | 기법 | 그룹 | w | 무엇을 보나 |
|---|---|---|---|---|
| `maAlign` | 정배열/역배열 | 추세 | 3 | MA5·20·60의 순서 |
| `maCross` | 골든/데드크로스 | 추세 | 3 (교차 없으면 2) | MA20×MA60, 최근 `TA_CROSS_LOOKBACK`일 안의 교차만 "발생" |
| `disparity` | 이격도 | 가격대 | 2 (약할 땐 1) | 종가 vs MA20 (%) |
| `trendSlope` | 중기 추세 | 추세 | 3 | MA60의 20거래일 변화율 |
| `macd` | MACD | 모멘텀 | 3 (교차 없으면 2) | 히스토그램 부호 전환 + 증감 |
| `rsi` | RSI(14) | 모멘텀 | 2 (중립권 1) | 70/30 + 50선 통과 |
| `bollinger` | 볼린저밴드 | 변동성 | 2 | %B 위치 + 밴드폭(≤8% = 스퀴즈) |
| `stochastic` | 스토캐스틱(14,3,3) | 모멘텀 | 2 (중립 1) | %K×%D 교차 + 80/20 |
| `volume` | 거래량 | 수급 | 2 (평범 1) | 20일 평균 대비 + 상승/하락일 여부 |
| `breakout` | 신고가/신저가 돌파 | 가격대 | 3 (박스권 2) | 직전 `TA_BREAKOUT_LOOKBACK`일 고·저 |
| `levels` | 지지·저항 근접 | 가격대 | 2 (중간 1) | 현재가에서 가장 가까운 기준선까지의 거리 |
| `trendline` | 추세선 | 가격대 | 3 (근접 2, 이격 1) | 스윙 점 2개를 이은 대각선 대비 위치 |

`levels` 후보는 두 종류다 — ①스윙 피벗(최근 120봉에서 앞뒤 5봉보다 낮은/높은 극값) ②최근 `TA_LEVEL_RECENT_BARS`봉의 고·저. 둘을 합쳐 **현재가에서 가장 가까운 것**을 고른다. 피벗만 쓰면 한 방향으로만 흐른 구간에서 거의 안 잡힌다(상승장에서는 정의상 골짜기가 생기지 않는다) — SK하이닉스가 800k→3.2M 상승 후 조정 중일 때 지지선이 넉 달 전 808,000(현재가 −42%)으로 찍혔다. 후보가 한쪽에 하나도 없으면 `null`을 낸다. 신저가 종목의 "지지선"처럼 없는 값을 억지로 만들지 않는다.

**합산** `_composite()` = `Σ(방향 × weight × strength) / Σweight × 100` → `-100 ~ +100` 정수.
중립 판정도 **분모에 들어간다** — 그래야 12개 중 2~3개만 강세인 종목이 강한 신호로 둔갑하지 않는다. 구간 라벨은 `TA_SIGNAL_BANDS`.

**행동 신호** `_action()` — 점수 위에 얹는 별도 판정. 같은 "매수 우위"라도 이미 크게 오른 자리인지 눌린 자리인지가 점수로는 구분되지 않는데, 실제로 궁금한 건 그 차이다.

| 우선순위 | key | 조건 |
|---|---|---|
| 1 | `stopLoss` | 신저가 이탈 + MA60 기울기 ≤ 0, 또는 하락추세에서 지지선 근접 & 점수 < 0 |
| 2 | `chase` | 상승추세 + 신고가 돌파 + (거래량 강세 or MA60 기울기 ≥ 2%) + 점수 > 0 |
| 3 | `addBuy` | 상승추세 + 20일선 ±`TA_PULLBACK_BAND`% + RSI 35~62 + 점수 ≥ -10 |
| 4 | `takeProfit` | RSI ≥ 70 또는 볼린저 상단 돌파, 점수 > 0 |
| 5 | `buy` | 골든크로스 발생, 또는 점수 ≥ 25 & 기울기 > 0 |
| 6 | `reduce` | 데드크로스 발생, 또는 점수 ≤ -25 |
| 7 | `rebound` | 하락추세 + RSI ≤ 30 |
| 8 | `hold` | 나머지 |

손절이 1순위인 것은 의도다 — 좋은 신호와 겹쳐도 손실 관리를 먼저 보여준다.

**비용 0** — 전부 결정론적 pandas 계산이라 LLM 예산도 네트워크도 쓰지 않는다. 184종목 전체가 sync 한 번에 8~11초.

> **NaN 주의**: `Series.replace(0, pd.NA)`를 쓰면 series가 object dtype이 되어 뒤의 `rolling().mean()`이 `No numeric types to aggregate`로 죽는다. 14일 내내 값이 같은 얇은 ETF가 실제로 여기에 걸렸다(2026-08-02). 분모 0은 `float("nan")`으로 둔다 — `tests/test_technical.py::test_flat_prices_do_not_crash`가 지킨다.

### 5.9 링크 (`analyze/link.py`)

**뉴스 → 종목 태깅** `tag_tickers()`
- 종목별 검색어(needle)와 가중치: 표시명 0.85, 별칭 0.75, KR 6자리 코드 0.95(모호성 없음), US 티커 0.9, 영문명 0.85.
- 매칭은 제목+요약 대상. `contains_token()`은 **한글은 부분문자열**, ASCII 영숫자는 단어 경계 정규식(그렇지 않으면 `V`가 모든 문장에 걸린다).
- 제목에 등장하면 +0.1(최대 1.0). 종목당 최대 6개, 점수 내림차순.

**이벤트 → 뉴스 매칭** `attach_news()`
- 윈도 `event_window()`: 시장 현지 종가(KR 15:30 KST / US 16:00 ET) 기준 `[종가-1일, 종가)`. 백필은 `days_before=2, days_after=2`로 확장(다음날 "왜 떨어졌나" 기사도 근거가 되므로).
- 관련도 `_relevance()`:

```
score = sourceWeight (기본 0.7)
      + 최고 종목 매칭 점수
      + min(1, max(0, (24 - 종가까지_남은시간h)/24)) * 0.4   # 종가에 가까울수록 원인 가능성↑
      + 0.35  (감성이 등락 방향과 일치)  |  -0.2 (반대 방향)
      + min(dupCount-1, 3) * 0.1                            # 널리 보도된 기사
```
- 상위 `max_items`(기본 5)만 `{title, url, source, publishedAt, score}`로 부착.

### 5.10 뉴스 스코어링 (`analyze/score.py`)

**카테고리** — 종목 매칭 점수 ≥0.85면 `"종목"`, 그 외 키워드 규칙으로 `정책/실적/산업/국제/암호화폐/시장` (미매칭 기본 `"시장"`).

**importance (0~100)**

| 항목 | 배점 | 계산 |
|---|---|---|
| 매체 신뢰도 | 30 | `sourceWeight × 30` |
| 최신성 | 20 | `20 × clamp((48-경과h)/45)`, 시각 불명이면 8 |
| 유니버스 종목 언급 | 20 | `20 × 최고 매칭 점수` |
| 시장 영향 키워드 | 20 | `min(히트수, 4) × 5` (KR+EN 사전) |
| 중복 보도 | 10 | `min(dupCount-1, 5) × 2` |

**enrich()** — category/importance/sentiment/tags 부착, `_dedup` 제거, importance 내림차순 정렬. 태그는 비ASCII 키워드 + 상위 종목명 2개, 최대 5개.

### 5.11 시장 분위기 (`analyze/mood.py`)

가중 평균(실제 존재하는 항목만으로 정규화):

| 요소 | 가중치 | 정규화 |
|---|---|---|
| 대표지수 등락 (KR=`KS11`, US=`US500`) | 0.40 | `(changePct + 2) / 4` → -2%~+2%가 0~1 |
| 상승 종목 비율(movers 기준) | 0.25 | `ups / (ups + downs)` |
| VIX 역방향 | 0.15 | `(30 - VIX) / 20` |
| USD/KRW 역방향 (**KR만**) | 0.10 | `(1 - changePct) / 2` |

점수 밴드: `≥65 양호(green)` / `≥35 중립(amber)` / `그 외 위축(red)`. 데이터가 하나도 없으면 50/중립.
`reason`은 "코스피가 0.42% 하락, 주요 종목 중 3개 상승·5개 하락, 공포지수(VIX) 18선으로 안정합니다." 형태로 조립.

### 5.12 이벤트 해설 (`analyze/summarize.py`)

**1패스 — 규칙 요약 (모든 이벤트)** `_rule_explain()`
- 뉴스 있음: `headline` = 최상위 기사 제목 30자 절단, `explain` = "이 날 X은(는) N% 올랐습니다/내렸습니다. 비슷한 시점에 "…" 등의 뉴스가 있었습니다. …". 신뢰도는 **근거 강도**로 산정 — 기사 3건 이상 & 최상위 점수 ≥1.6 → medium, 2건 이상 & ≥1.4 → medium, 그 외 low (규칙 기반은 medium이 상한).
- 뉴스 없음: `headline` = `label_for()`, "뚜렷한 개별 뉴스는 찾지 못했습니다. 시장 전체 흐름이나 수급 영향일 수 있습니다.", confidence low.
- `source: "rule"`.

**2패스 — 전역 AI 해설** `enhance_globally(details)`
- 후보: 뉴스가 붙어 있고 `LLM_RECENT_DAYS`(60일) 이내인 모든 종목의 이벤트.
- 정렬 키: `(severity, |changePct|, 기사 수, date)` 내림차순 → 상위 `LLM_MAX_EVENTS_PER_RUN`(60)만.
- Gemini 결과로 `headline/explain/sentiment/confidence/tags`를 덮고 `source: "llm"`으로 승격. 실패하면 규칙 요약이 그대로 남는다.
- 종목별이 아니라 **유니버스 전체에서 상위 선별** — 무료 쿼터를 가장 중요한 사건에 쓰기 위함.

### 5.13 Gemini 클라이언트 (`analyze/llm.py`)

런 단위 전역 상태: `_budget`(남은 이벤트 해설 수), `_calls`, `_disabled`, `_consec_429`. `reset()`을 sync 시작 시 호출.

`_post(prompt)` 흐름:
1. 매 호출 전 `GEMINI_DELAY_SEC`(7초) sleep — 무료 RPM 준수.
2. `429` → `_consec_429++`, 6·12초 백오프 재시도. **3회 연속이면 런 전체에서 LLM 비활성화**(서킷 브레이커).
3. `400/403/404`(잘못된 키·모델·요청) → 재시도 없이 즉시 비활성화.
4. `5xx` → 재시도.
5. 성공 → `candidates[0].content.parts` 텍스트를 JSON 파싱. `_loads()`가 마크다운 코드펜스와 앞뒤 잡음을 견디도록 `[…]`/`{…}` 스팬 폴백까지 시도.
6. `candidates`가 비면 `promptFeedback.blockReason`을 로그.

3개 작업:

| 함수 | 프롬프트 요지 | 출력 |
|---|---|---|
| `explain_events(items)` | "주식 초보자를 위한 한국어 해설가. 2~3문장, 존댓말, 전문용어는 즉시 풀어쓰기, 근거 약하면 '~로 보입니다' + confidence low, **매수/매도·목표가 금지**" | `[{id, headline(≤30자), explain, sentiment, confidence, tags[]}]` |
| `brief_summary(label, snapshot, headlines, mood)` | 개장 전 브리핑 headline 1개 + 3줄 요약 | `{headline, threeLines[3]}` |
| `translate(texts)` | 영문 금융 문장 → 자연스러운 한국어, 고유명사·티커 유지 | `[{i, ko}]` (실패 슬롯은 원문 유지) |

`available()` = `LLM_ENABLED and 키 있음 and not _disabled`. `stats()`로 호출 수·남은 예산 로깅.

### 5.14 오케스트레이션 (`build/site_data.py`)

#### `build(markets)` — 전체 sync, 6단계

| 단계 | 내용 |
|---|---|
| 1/6 | `universe.enrich()` → 시장 필터 |
| 2/6 | 시장 뉴스 수집 → 종목 태깅 → 스코어링 → **피드 번역 우선 패스**(번역이 ON일 때만; 이벤트 요약보다 먼저 쿼터를 쓰게) |
| 3/6 | 종목별 루프: `_build_ticker()` |
| 4/6 | `summarize.enhance_globally()` (전역 상위 AI 해설) + 종목 뉴스 번역(캐시 재사용) |
| 5/6 | 종목 JSON 기록 + `index.json` 엔트리 생성 |
| 6/6 | 매크로 수집 → **이전 공유 파일과 병합** → `overview.json` → `news/latest.json` → `manifest.json` |

#### 부분 빌드의 공유 파일 병합 (2026-07-28)

`index.json` · `overview.json` · `news/latest.json` · `manifest.json`은 **시장별 파일이 아니라
한 덩어리**다. `build(("US",))`처럼 부분 빌드가 이걸 통째로 덮어쓰면 다른 시장 데이터가 사라진다.
`brief-*` 워크플로가 `--rebuild`로 단일 시장 빌드를 돌리기 때문에 **실제로 발생했다** —
2026-07-27 brief-us 실행 후 `index.json`에 US 62종목만 남고 KR이 0건이 되어, 웹 국장 탭이
"데이터 로딩 중…"에서 멈췄다. 반나절 뒤 data-sync(전체)가 복구하고, 다음 brief가 반대쪽을
다시 지우는 것이 반복되고 있었다.

지금은 쓰기 전에 이전 파일을 읽어 **이번에 빌드하지 않은 시장의 몫을 살려서 합친다**:

| 대상 | 병합 방식 |
|---|---|
| `index.json` | `_merge_by_market()` — 이전 항목 중 `market`이 이번 대상이 아닌 것만 유지 |
| `news/latest.json` | `_merge_news()` — 같은 원리 + url 중복은 이번 빌드 우선. `GLOBAL` 뉴스는 어느 시장 빌드에서도 나와서 `markets` 필터에 안 걸리는데, url dedupe가 그 몫을 처리 |
| `overview.json` | `sectors`/`movers`/`marketMood`를 이전 dict 위에 대상 시장만 덮어씀. `indices`(매크로)는 시장 무관하게 매번 전체 수집이라 그대로 교체 |
| `manifest.json` | `markets` 블록을 이전 값 위에 대상 시장만 덮어씀 |

`build_pulse()`에도 같은 처리를 넣었다(CI는 항상 전체 시장으로 돌려서 잠복 상태였다).
전체 빌드(`markets=("KR","US")`)일 때는 이전 항목이 전부 필터링되므로 **기존과 동일한 결과**다.

`_build_ticker(meta, market_news)`:
1. 일봉 수집(실패 시 `None` → 스킵), `quote` + 시총 병합
2. `events.detect()`
3. 뉴스: 해당 종목으로 태깅된 시장 뉴스 + (ETF 아니면) 종목별 뉴스 → dedupe → 스코어링
4. `link.attach_news()` → (ETF 아니면) `_backfill_event_news()` → `summarize.summarize_events()`(규칙)
5. 반환: `code/name/nameEn/market/exchange/sector/currency/updatedAt/quote/ohlcv/indicators/events/recentNews(10)/_spark`
   (`_` 접두 필드는 파일에 쓰지 않고 index 생성에만 사용)

`_backfill_event_news()` — 뉴스 없는 이벤트 중 200일 이내인 것을 `(severity, |changePct|)` 내림차순으로 최대 6개, 날짜 지정 Google News 조회 → 넓은 윈도(±2일)로 매칭 → 최대 5건 부착.

파생 산출물:
- `_sector_heatmap()` — 섹터별 평균 등락률 + 종목 수 + 대표(최고 등락) 종목, 등락률 내림차순
- `_movers()` — 상승 8 / 하락 8 (`reason`은 overview를 가볍게 유지하려 `null`, 브리핑에서 이벤트 headline으로 채움)
- `_manifest()` — version 1, 생성 시각(UTC/KST), counts(tickers/news/events), 시장별 `lastTradingDay`·`briefDate`

#### `build_pulse(markets)` — 경량 갱신

매크로 + 뉴스 + 분위기만 다시 계산(2분 내). 종목 루프·이벤트·LLM 전부 스킵.
- 유니버스는 `enrich()`(느린 상장목록 조회) 대신 `all_universe()`를 사용 — 태깅에 필요한 건 코드/이름/별칭뿐.
- `sectors`/`movers`는 직전 full sync의 `overview.json`에서 **그대로 이어받고**, 그 movers로 분위기를 다시 계산.
- `manifest.json`은 `generatedAt`/`generatedAtKst` + **`markets[*].briefDate`**를 갱신
  (counts와 `lastTradingDay`는 마지막 full sync 값 유지 — 종목 데이터가 있어야 구한다).
  `briefDate`는 웹이 "오늘 브리핑이 아직 안 나왔다"를 판정하는 기준값이라(§7 Brief)
  full sync(하루 2회)에만 맡기면 반나절씩 옛 날짜가 남는다. pulse가 2시간마다 밀어 준다.

#### 번역 캐시

런 스코프 딕트 `_TRANS: {원문 → 한국어}`. `_translate_feed()`가 US/GLOBAL 뉴스 중 importance 상위 20건의 제목·요약을 번역해 채우고, 전체 피드에 캐시 히트만 적용(`titleKo`/`summaryKo`). `_translate_ticker_news()`는 기본적으로 신규 호출 없이 캐시만 재사용. 현재 `TRANSLATE_FOREIGN=False`이므로 두 함수 모두 실질적으로 no-op.

### 5.15 브리핑 (`build/brief.py`)

- 대상 시장 + `GLOBAL` 뉴스만 골라 importance 내림차순.
- `date` = `next_session_date(market)` (KR은 KST 기준 오늘, US는 ET 기준 오늘. 휴장이면 다음 거래일까지 최대 10일 전진).
- `marketSnapshot` 키 구성: KR → `US500, IXIC, USD/KRW, ^TNX` / US → `US500, IXIC, VIX, CL=F`.
- `topNews` 6건, 각 항목에 `_why()`로 **초보용 한 줄 이유**를 붙인다(키워드 규칙 5개 → 종목 언급 → 기본 문구).
- `watchlistMoves` = 상승 상위 3 + 하락 상위 2, `note`는 해당 종목 JSON의 최신 이벤트 `headline`.
- `headline`/`threeLines`는 Gemini → 실패 시 `_rule_summary()`(간밤 지수·환율·최상위 뉴스로 3줄 조립).
- `calendar`는 예약 필드(빈 배열) — 경제 캘린더 소스는 미도입.
- 기록: `brief/latest-{MARKET}.json` + `brief/{date}-{MARKET}.json` 아카이브.
- 고정 면책: "본 브리핑은 공개된 뉴스를 정리한 정보이며 투자 권유가 아닙니다."

### 5.16 텔레그램 (`notify/telegram.py`)

- `render(brief)` — HTML parse mode. 구성: 제목(국장 📈 / 미장 🌙) → 날짜 → 분위기 신호등 → headline → `📌 오늘 꼭 알아야 할 3가지` → `📊 간밤 시장` → `📰 주요 뉴스`(제목 링크 + `💡 왜 중요한가` + `🏷 종목·매체`) → `👀 관심 종목 움직임` → 사이트 링크 → 면책.
- 색 규칙: 상승 🔴 / 하락 🔵 (사이트와 동일한 한국식).
- `html.escape`로 전부 이스케이프. `disable_web_page_preview=true`.
- 4096자 제한 대비 `_LIMIT = 3900`에서 **줄 단위 분할** 전송.
- `send()` — 토큰/chat_id 없으면 경고만 남기고 `False`. `_post()`는 3회 재시도(429는 지수 백오프 `2**attempt`, 그 외 HTTP 에러는 즉시 실패).
- `whoami(token)` — `getUpdates`로 봇에게 말 건 chat_id 목록 출력(셋업 헬퍼).

### 5.17 유틸리티

**`util/dates.py`**
- 저장은 항상 UTC ISO8601 + `Z`(`iso()`), 파싱은 `parse_iso()`(`Z` → `+00:00`, naive는 UTC 가정).
- `KR_HOLIDAYS_2026`(22일), `US_HOLIDAYS_2026`(10일) 하드코딩 + 주말 → `is_trading_day()`. 누락되면 브리핑이 한 번 더 나갈 뿐인 안전한 실패.
- `next_session_date(market)` — KR은 KST, US는 ET 로컬 날짜에서 시작해 거래일까지 전진.

**`util/io.py`**
- `write_json()` — 부모 디렉터리 생성, `_clean()`으로 NaN/Inf → `null`(+ float 6자리 반올림, numpy 스칼라는 `.item()`), `ensure_ascii=False`, 구분자 압축, **tempfile + `os.replace` 원자적 교체**(중단된 런이 반쪽 JSON을 남기지 않게). 실패 시 임시파일 정리.
- `read_json(path, default)` — 예외는 경고 후 default.
- 디스크 캐시 `cache_get/cache_set` (`.cache/{key}.json`, mtime 기반 TTL).

**`util/text.py`**
- `clean_html()`(태그 제거 + 엔티티 언이스케이프 + 공백 정규화), `strip_source_suffix()`(Google News의 " - 매체명" 제거), `normalize_url()`(추적 파라미터 13종 + 프래그먼트 제거, 호스트 소문자, 말미 `/` 제거), `dedup_key()`, `news_id()`, `truncate()`, `sentiment_of()`(어휘 사전 카운트), `contains_token()`(한글 부분문자열 / ASCII 단어경계).

**`util/log.py`** — `[  12.3s] ✓ 메시지` 형태. `err`만 stderr. `UnicodeEncodeError` 시 ASCII 치환 재출력(Windows 콘솔 대비).

## 6. 데이터 계약 (실제 출력 기준)

경로: 웹은 `/data/...`로 fetch. 배포 빌드는 `data/` → `web/public/data/` 복사본을,
dev 서버는 레포 `data/`를 직접 읽는다(§8.1).

### 6.1 `manifest.json`

```json
{"version":1,"generatedAt":"2026-07-25T05:44:24Z","generatedAtKst":"2026-07-25 15:06",
 "counts":{"tickers":184,"news":779,"events":4260},
 "markets":{"KR":{"lastTradingDay":"2026-07-24","briefDate":"2026-07-27"},
            "US":{"lastTradingDay":"2026-07-23","briefDate":"2026-07-27"}}}
```

### 6.2 `market/overview.json` (실측 ~11KB)

`generatedAt`, `indices[12]`(§5.6 필드), `sectors: {KR:[], US:[]}`, `movers: {KR:{up[8],down[8]}, US:{…}}`, `marketMood: {KR:{score,label,color,reason}, US:{…}}`.
`MoverRef` = `{code, name, market, changePct, close, reason(null)}`.

### 6.3 `tickers/index.json` (실측 ~88KB / 184종목)

종목당: `code, name, nameEn, market, exchange, sector, currency, close, changePct, marcap, spark[30], eventCount, latestEvent, analysis?, date`.
`analysis`는 §6.4 판정의 압축본(`score, signal, label, action, actionEmoji, actionLabel, headline, date`) — 목록·브리핑이 종목 파일을 열지 않고 신호를 띄우게 한다. 이력이 짧으면 `null`.

### 6.4 ⭐ `tickers/{KR|US}/{code}.json` (지표 6종 추가 후 실측 평균 ~112KB)

```jsonc
{
  "code","name","nameEn","market","exchange","sector","currency","updatedAt",
  "quote": { date, open, high, low, close, prevClose, change, changePct,
             volume, volumeVsAvg20, high52, low52, marcap },
  "ohlcv": { "columns": ["d","o","h","l","c","v"], "rows": [["2024-07-22",…], …] },  // ~508행
  "indicators": { "ma5","ma20","ma60","ma120","rsi14","volMa20",                     // rows와 동일 길이
                  "bbUpper","bbLower","macd","macdSignal","macdHist" },
  "analysis": {                                                 // §5.8 · 이력 부족 시 null
      date, score, signal, label, action, actionEmoji, actionLabel, actionNote,
      headline, summary,
      trend: { phase, direction, slopePct, label, aboveMa60 },
      counts: { bullish, bearish, neutral },
      signals: [ { key, name, group, verdict, strength, weight, value, detail } ],  // 최대 12개
      levels: { support, resistance, supportGapPct, resistanceGapPct, high52, low52 },
      risk: { atrPct, band }, disclaimer
  },
  "events": [ {
      id, date, type, severity, changePct, zScore, volumeRatio, gapPct, close, volume,
      headline, explain, confidence, sentiment, source, tags[],
      news: [ { title, url, source, publishedAt, score } ]   // 최대 5
  } ],                                                        // 최대 40, 날짜 내림차순
  "recentNews": [ NewsItem ]                                  // 10건
}
```

### 6.5 `news/latest.json` (실측 ~250KB)

`{generatedAt, items: NewsItem[]}` — importance 내림차순, 최대 400건.
`NewsItem` = `id, title, titleKo?, summary, summaryKo?, url, source, market, publishedAt, category, tags[], tickers[], importance, sentiment`.
(종목 상세의 `recentNews`도 동일 형태의 축약본. `sourceKey`/`sourceWeight`/`dupCount`는 내부 필드로 최종 출력에는 남지 않는다 — `_news_brief()`가 화이트리스트로 추림.)

### 6.6 `brief/latest-{KR|US}.json`, `brief/{date}-{MARKET}.json`

`market, date, generatedAt, headline, threeLines[3], mood{score,label,color}, marketSnapshot[], topNews[6], chartSignals, watchlistMoves[5], calendar[](빈), disclaimer, siteUrl`.
**텔레그램 메시지와 웹 브리핑 카드가 같은 객체를 사용** → 두 채널이 어긋날 수 없다.

`chartSignals` = `{asOf, counts{bullish,neutral,bearish}, bullish[≤TA_BRIEF_PICKS], bearish[…], note}`.
`index.json`의 `analysis` 압축본을 모아 만들 뿐이라 브리핑 전용 재계산이 없다.
`watchlistMoves[]`에도 `signal`(= `actionLabel`)·`signalEmoji`가 붙는다.
`_tech_line()`이 만든 한 줄("차트 지표 기준으로 추적 종목 N개 중 매수 우위 …")은
LLM 3줄 요약 프롬프트에도 들어가고, 키가 없을 때 규칙 요약의 한 줄로도 쓰인다 —
같은 문장을 두 경로가 공유해서 내용이 갈리지 않게 한다.

### 6.7 규약

| 항목 | 규칙 |
|---|---|
| 시각 | 저장은 UTC ISO8601 + `Z`. 표시할 때만 KST/ET |
| 날짜 | 거래일은 시장 현지 `YYYY-MM-DD` |
| 숫자 | `null` 허용, `NaN`/`Infinity` 금지(`io._clean`이 보장) |
| 인코딩 | UTF-8, `ensure_ascii=false` |
| 결측 | 키를 지우지 않고 `null`/`[]` |
| 파일명 | 미장 티커 대문자, 국장 6자리 문자열(앞 0 유지) |
| 쓰기 | 원자적 교체(임시파일 → `os.replace`) |

### 7.2 데이터 접근 (`lib/api.ts`, `lib/useAsync.ts`)

- `get<T>(path, cacheKey)` — `fetch(`${BASE}/data/${path}`, {cache:"no-cache"})`. 성공하면 `localStorage["sp:"+cacheKey]`에 최종 성공본 저장. **실패하면 캐시본을 반환**(오프라인/갱신 실패에도 화면이 뜬다). 쿼터 초과는 무시.
- API 메서드: `manifest, overview, tickers, ticker(market,code), news, brief(market)`.
- `useAsync(fn, deps)` — `{data, loading, error}`. `alive` 플래그로 unmount 후 setState 방지. deps 배열로 재조회.

### 7.3 설정 컨텍스트 (`lib/settings.tsx`)

| 설정 | 기본값 | localStorage 키 | 효과 |
|---|---|---|---|
| `beginner` | **true** | `sp:beginner` | 차트를 종가선으로, MA는 20일만, 마커/이벤트 필터, "많이 올랐어요" 라벨 |

파생 값 `upColor`/`downColor`/`colorFor(pct)`를 제공해 모든 컴포넌트가 색 규칙을 한 곳에서 가져간다.
워치리스트는 별도로 `sp:watch`(`["KR:005930", …]`)에 저장 — `Ticker.tsx`의 지역 함수가 관리.

### 7.4 페이지 구현

**Home** — 오늘 날짜(`manifest.markets.KR.briefDate`), 분위기 카드 2개(KR/US), 매크로 카드 가로 스크롤(`group`이 index/fx인 것 상위 8), 주요 뉴스 6건, 국장/미장 바로가기, 하단에 면책 + 마지막 갱신(KST). 로딩은 스켈레톤, `overview` 실패 시 빈 상태 카드.

**Market** — 시장별 분위기, 매크로 스트립(해당 시장 + GLOBAL), 섹터 히트맵(등락 방향으로 테두리 색), 상승/하락 상위 리스트, 전체 종목 행(이름 + 이벤트 수 📍N + 섹터·시총 + 스파크라인 + 가격 + 등락).

**Ticker** — 헤더(가격/등락/거래량 배수/⭐차트분석 칩), 기간 칩(1M/3M/6M/1Y/2Y = 22/66/132/252/500 거래일, 기본 132), 지표 토글 6종, 차트, ⭐ 차트 분석 카드, 4개 스탯(시총·52주 최고/최저·전일종가), ⭐ 급등락 타임라인, 최근 종목 뉴스, ♥ 관심 토글.
- 지표 토글은 `Overlays` 한 객체(`markers/ma/bb/macd/rsi/levels`)로 관리. 기본값은 `markers`·`levels`만 ON — 처음 열었을 때 선이 많으면 초보자가 아무것도 못 읽는다.
- `AnalysisCard`: 행동 문구가 주인공(점수는 우측 곁들이) → 점수 막대 → `actionNote` → `summary` → 지지/저항/추세/변동성 4칸 → **52주 고·저 대비** → **추세선** → **기법별 판정 12줄**(누르면 `detail` 펼침) → 면책 + `/learn?tab=chart` 링크. 12줄은 항상 전부 편다 — 접어 두면 "왜 이 판정인지"를 못 따라간다.
- 이벤트 카드: 날짜·등락·거래량배수·종가 / `headline` / `explain` / 신뢰도 신호등(🟢높음 🟡보통 🟠낮음) + `AI 요약` 표시 + 태그 / 관련 기사 링크.
- 차트에서 캔들 클릭 → 상세 패널의 버튼 → `jumpToEvent()`가 해당 이벤트 카드로 스크롤 + 하이라이트.

**News** — 필터 칩 `전체/국장/미장/정책/실적/산업/종목`(국장=`market KR`, 미장=`US|GLOBAL`, 나머지는 `category` 일치), 40건씩 "더 보기".

**Brief** — KR/US 토글, 분위기·3줄 요약·간밤 시장·주요 뉴스(💡 why 포함)·**📊 차트 분석 신호**·관심 종목 움직임·면책. 없으면 "매일 장 시작 전에 자동으로 만들어집니다" 안내.
차트 분석 신호는 뉴스 섹션과 섞이지 않게 별도 카드로 두고(근거가 지표뿐이라는 점이 흐려지면 안 된다), 강세/약세 2열 + 종목 링크 + `note` 면책 + 도움말 링크로 구성한다.

들고 있는 브리핑이 `manifest.markets[시장].briefDate`보다 오래됐으면 위에 **"⏳ N월 N일
브리핑은 아직 준비 중이에요"** 안내를 띄운다. 2026-07-28에 브리핑이 안 나갔을 때 화면이
월요일 것을 아무 표시 없이 보여줘서, 사용자가 날짜를 직접 대조하고서야 알아챘다.
`manifest`는 브리핑과 **따로** 받는다 — 못 읽어도 브리핑 본문은 그대로 보인다.
비교는 `date < briefDate` 단방향이라 manifest 쪽이 더 낡았을 땐 침묵한다(헛경보 방지).

**Learn (도움말)** — 탭 2개. 탭 상태는 `?tab=chart` 쿼리스트링(분석 카드·브리핑에서 링크로 착지해야 한다).
- **📖 용어사전** — `terms.ts` 39항목을 5그룹으로 분류 표시(기본 용어 / 차트 보는 법 / 시장 구조 / 거시 경제 / 실적·이벤트).
- **📊 차트분석** — 봉 해부도 → **지표 색 약속** → 기법 12가지(`chartGuide.ts`) → 합산 방식·점수 구간 표 → 행동 신호 8가지 → 한계 4가지. 각 기법은 "무엇을 재나 / 예시 차트 / 강세·약세로 읽는 법 / **언제 틀리나**" 4단.
- 색 약속 절은 `INDICATOR` 8종을 색 견본 + 이름 + "그래서 뭘 보는 선인지" 한 줄로 늘어놓는다. 예시 차트마다도 아래에 같은 견본 범례가 붙어서, 그림을 보다가 색이 헷갈리면 바로 대조된다.
- `chartGuide.ts`의 `key`는 `technical.py`의 signal key와 **1:1**이다. 종목 화면 "기법별 판정"에서 본 이름이 도움말에도 그대로 있어야 한다.
- 예시 차트는 캡처가 아니라 `PatternChart.tsx`가 값 배열로 그리는 SVG다. 이동평균·볼린저·RSI·MACD·스토캐스틱을 TS로 **실제 공식대로 계산**해서 그리므로 종목 차트와 모양·색이 일치한다. 이미지였다면 테마 전환·반응형·색 규칙 변경에서 조용히 어긋난다.
- **캔들로 그린다.** 시리즈는 `N=130`으로 계산하고 마지막 `VIS=55`봉만 렌더링한다(`visible` prop). 60일선은 60봉을 먹고 시작하므로 짧은 시리즈를 통째로 그리면 60일선이 오른쪽 3분의 1에만 나오고, 130봉을 다 그리면 봉 하나가 2px 실선이 된다. 종목 차트가 기간 칩으로 하는 일과 같은 절충이다. `toBars()`가 종가 배열 → OHLC를 결정론적으로 만든다(지표 계산은 전부 종가 기준이라 시·고·저는 그림 전용).
- 마커 좌표는 계산해서 얻는다 — `crossIndex()`(골든크로스·MACD 교차), `firstAbove()`(돌파). 하드코딩하면 파형을 조금만 손봐도 점선이 엉뚱한 봉에 찍힌다. 지지·저항 가로선도 보이는 구간의 실제 최고·최저에서 뽑는다.
- MACD 예시만 별도 시리즈(`P.macdTurn`)를 쓴다. MACD(12/26)는 이동평균 크로스보다 빨리 반응해서, 골든크로스용 파형을 그대로 쓰면 정작 설명할 상향 교차가 보이는 구간 밖에서 끝난다.

## 8. 빌드 · 배포

### 8.1 npm 스크립트 (`web/package.json`)

```
copy-data : node scripts/copy-data.mjs
predev    : copy-data      → dev 전에 자동 실행
dev       : vite           (포트 5173)
prebuild  : copy-data
build     : tsc -b && vite build
preview   : vite preview
```

`copy-data.mjs` — 루트 `data/`를 `web/public/data/`로 통째 복사(기존 것은 `rm -rf` 후 재생성). `data/`가 없으면 로그만 남기고 정상 종료(신규 체크아웃 대응). 산출물이므로 `.gitignore`에 등록되어 추적하지 않는다. **`prebuild` 에서만 돈다** — 정적 호스팅은 사본이 필요하기 때문이다.

`vite.config.ts` 의 `serveRepoData` 플러그인 — dev 서버(`apply: "serve"`)에서 `/data/*` 를 레포 `data/` 에서 직접 읽어 응답한다. 예전에는 `predev` 훅이 같은 복사를 돌렸는데, 복사가 서버 기동 시 한 번뿐이라 그 뒤 `git pull` 이나 로컬 파이프라인 실행으로 원본이 바뀌면 화면이 옛 스냅샷에 멈춘 채 아무 표시도 없었다(2026-07-28: 레포에는 07-28 미장 브리핑이 있는데 화면은 07-27 것을 보여줬고, 없는 파일은 SPA fallback 이 `index.html` 을 200 으로 돌려줘 그것마저 조용했다). 미들웨어는 `next()` 로 흘리지 않고 404/403 으로 직접 끝낸다 — 흘리면 `public/data` 에 남은 옛 사본이 조용히 응답해서 없애려던 침묵 실패가 되돌아온다. `data/` 밖으로 벗어나는 경로는 403.

### 8.2 Vercel (`web/vercel.json`)

```json
{"framework":"vite","buildCommand":"npm run build","outputDirectory":"dist",
 "rewrites":[{"source":"/((?!data/).*)","destination":"/index.html"}]}
```
SPA 라우팅용 rewrite이지만 **`/data/`는 제외** — 그렇지 않으면 JSON 요청이 index.html로 리라이트되어 파싱 에러가 난다. Root Directory는 `web`.
배포 트리거는 워크플로의 `git push`(data 커밋) → Vercel 자동 재배포.

### 8.3 TypeScript

`strict`, `noUnusedLocals`, `noUnusedParameters`, `noFallthroughCasesInSwitch`, `noEmit`, `moduleResolution: bundler`, `jsx: react-jsx`, target/lib ES2022. 빌드는 `tsc -b`가 먼저 통과해야 `vite build`가 돈다.

### 9.1 워크플로 5종

| 파일 | cron (UTC) | 현지 | 명령 | 하는 일 |
|---|---|---|---|---|
| `data-sync.yml` | `30 7,21 * * 1-5` | 평일 16:30 / 06:30 KST | `sync` | 장 마감 후 전체 재계산 |

| `test.yml` | (cron 없음) | — | `pytest tests` | `pipeline/**`·`brief-*.yml` 변경 푸시에서만 |

전부 `workflow_dispatch` 수동 실행 가능. 공통 구조: `checkout@v4`(**`ref: main`**) → `setup-python@v5`(3.12, pip 캐시) → `pip install -r requirements.txt` → 실행 → `.github/scripts/commit-data.sh`.

- `ref: main` — 스케줄 트리거는 *예약 시점*의 SHA를 준다. 최대 3시간 밀려 깨어나므로
  명시하지 않으면 오래된 트리 위에서 판정·커밋하게 된다.
- concurrency: `data-sync`/`pulse`는 `stock-pulse-data`를 공유하고, `brief-kr`/`brief-us`는
  **각자 자기 그룹**(`stock-pulse-brief-KR|US`)을 쓴다. 예전에는 브리핑도 같은 그룹이라
  26분짜리 `data-sync` 뒤에 큐잉되면서 발송 창을 통째로 놓칠 수 있었다.
- `permissions: contents: write` — 봇 커밋용.
- 커밋·푸시는 `.github/scripts/commit-data.sh` 하나로 통일. 거절되면 `origin/main` 위로
  `git rebase -X theirs` 후 재시도(최대 5회) — 충돌 시 방금 만든 데이터를 채택한다.
  단발 푸시로 두었던 `data-sync.yml`이 2026-07-27 `! [rejected] (fetch first)`로
  25분치 재계산을 통째로 날린 뒤 도입했다.
- `brief-kr`의 `0-4`(일~목) UTC = 월~금 KST — **요일이 하루 밀리는 점 주의**
  (`tests/test_schedule.py::test_weekday_spec`가 지킨다).

### 9.1.1 브리핑 도착 시각 보장 (2026-07-28 개정)

목표는 **개장 30분 전 도착**인데, GitHub 스케줄러가 예약 시각을 지키지 않는다.
이 저장소 실측 지연:

| 워크플로 | 예약 | 실제 run 생성 | 지연 |
|---|---|---|---|
| pulse (2026-07-26) | 08:00 UTC | 08:06:54Z | +6분 |
| brief-kr (2026-07-28) | 23:23 UTC | 00:14:22Z | +51분 |
| brief-kr (2026-07-28) | 23:11 UTC | 00:09:40Z | +58분 |
| pulse (2026-07-27) | 00:00 UTC | 01:54:55Z | +114분 |
| brief-us (2026-07-27) | 12:30 UTC | 15:23:02Z | +173분 |
| data-sync (2026-07-27) | 07:30 UTC | 10:52:43Z | **+202분** |

`run_started_at == created_at`이라 concurrency 큐 대기가 아니라 스케줄러 자체 지연이다.

**2026-07-28 국장 브리핑 미발송 사고.** 슬롯이 23:11/23:23 UTC 둘뿐이었는데 GitHub이
둘 다 ~55분 밀려 깨웠다(09:09 / 09:14 KST). 발송 창 게이트가 (설계대로) 둘 다 막았고,
대체 슬롯이 없어 그날 브리핑이 통째로 나가지 않았다. 웹의 브리핑 카드도 같은 이유로
월요일에 멈춰 있었다 — 브리핑 JSON이 곧 웹 데이터원이기 때문이다.

지연 폭이 6~202분으로 널뛰므로 "슬롯 2개 + 좁은 창"으로는 구조적으로 못 맞춘다.
개정된 구조:

1. **슬롯을 지연 폭 전체에 깐다** — 목표 −4시간부터 40분 간격(KR 7개, US 9개).
   발송 창(55분) > 슬롯 간격(40분)이므로 **지연이 0~240분 어디에 걸리든 최소 한 슬롯이
   창 안에 떨어진다.** 이건 추정이 아니라 `tests/test_schedule.py`가 워크플로의 cron을
   직접 파싱해서 0~240분 전 구간을 검증한다(옛 배치는 241개 중 30개만 커버).
2. **발송 창 게이트**(`pipeline/gate.py`, 체크아웃 직후 첫 스텝) — 현지 실제 시각이
   창 밖이면 즉시 종료. 창 = **개장 75분 전 ~ 20분 전**(`config.BRIEF_WINDOW`):
   KR `07:45~08:40 KST`, US `08:15~09:10 ET`. 창 밖 슬롯은 15초에 끝난다.
   미장은 cron이 UTC 고정이라 EDT/EST 창을 모두 덮도록 깔고, 계절이 어긋난 쪽은
   이 게이트가 걸러낸다.
3. **중복·휴장 게이트** — 같은 판정 함수 안에서 처리한다. `data/brief/{세션}-{시장}.json`이
   이미 있으면 종료(뒤 슬롯이 `ref: main` 체크아웃으로 앞 슬롯의 커밋을 본다), 휴장일이면 종료.
4. **발송 경로에서 `--rebuild`를 뺐다** — 브리핑에 새로 필요한 건 매크로·환율·뉴스뿐이고
   종목·이벤트는 직전 `data-sync` 결과로 충분하다. `pulse --market X` → `brief --send`로
   바꿔 job이 11~19분에서 2~3분이 됐다. 슬롯을 3.5배로 늘렸는데도 총 사용 분은 줄었다(§12).
5. **발송 실패 시 잡을 실패시킨다** — `_cmd_brief`가 텔레그램 실패에 exit 1을 낸다.
   커밋 스텝까지 못 가므로 브리핑 파일이 안 올라가고 → 남은 슬롯이 자동으로 재시도한다.

> ⚠️ **로컬 `brief --dry-run` 결과를 커밋하지 말 것.** `run.py:_cmd_brief`는
> `--send` 여부와 무관하게 `write_brief()`를 호출하므로, 미리보기만 해도
> `data/brief/{오늘}-{시장}.json`이 생긴다. 이걸 커밋하면 중복 게이트가 그날 브리핑을
> 이미 나간 것으로 보고 **조용히 건너뛴다.** 미리보기 후에는
> `git checkout -- data/brief/` 로 되돌린다.

`workflow_dispatch`는 `--force`로 시각·중복 검사를 모두 건너뛴다(수동 dispatch run은
실측 13초 만에 시작하므로 지연 보정이 필요 없다). 휴장일 판정은 `_cmd_brief`가 따로 한다.

한계: 지연이 240분을 넘거나 모든 슬롯이 창을 벗어나면 **그날은 발송하지 않는다**
(개장 후 발송보다 낫다는 판단은 유지). 커버 범위를 넓히려면 `brief-*.yml` 앞쪽에
슬롯을 더 깔고 `tests/test_schedule.py`의 `MAX_DELAY_MIN`을 함께 올린다.

### 9.1.2 리허설 모드 (`send=false`)

```bash
gh workflow run brief-us.yml --ref main -f send=false
```

브리핑 경로가 실제 러너에서 도는지 **텔레그램을 건드리지 않고** 확인한다.
`workflow_dispatch`의 boolean 입력 `send`를 끄면:

- `brief`를 `--send` 없이 실행 → 메시지를 렌더해 로그에 출력만 한다
- **커밋 스텝을 건너뛴다.** 리허설 결과를 커밋하면 중복 게이트가 그날 진짜 발송을
  막아 버린다 — §9.1.1이 고치려던 사고를 손으로 재현하는 꼴이다

스케줄 실행은 이 입력과 무관하게 항상 발송한다(기본값이 `--send`이고, 리허설 분기는
`EVENT != schedule` 안에만 있다). 두 성질 모두 `tests/test_workflows.py`가 고정한다.

실측: 리허설 런 37초 (체크아웃 + 게이트 + `pip install` + `pulse` + 브리핑 생성/렌더).
디버깅용으로 `data-sync`(런당 22분)를 돌리는 대신 이쪽을 쓰면 Actions 분을 아낀다.

### 9.4 데이터 보관 (retention)

`data/`에서 **시간이 지날수록 무한히 늘어나는 것은 브리핑 아카이브 하나뿐이다.**
나머지는 이미 상한이 걸려 있다 — 종목 파일은 유니버스 크기에 비례하고(`HISTORY_YEARS`,
`EVENT_MAX_PER_TICKER`), 뉴스는 `NEWS_MAX_ITEMS`, 매크로는 고정 키 집합이다.

| 대상 | 정리 규칙 | 실행 시점 |
|---|---|---|
| `brief/YYYY-MM-DD-{market}.json` | `BRIEF_KEEP_DAYS`(30일)보다 오래된 것 삭제 | `build.brief.write_brief()` — 브리핑을 쓸 때마다 |
| `brief/latest-{market}.json` | 정리 대상 아님 | — |

`prune_briefs()`가 지키는 것:

- **기준일은 "오늘"이지 브리핑 날짜가 아니다.** 브리핑의 `date`는 *다음* 세션(=미래)이라,
  그걸 기준으로 잡으면 보관 창이 하루씩 밀린다.
- **시장별로 분리.** KR 정리가 US 파일을 건드리면 미장 브리핑이 중복 발송된다.
- **날짜로 파싱되지 않는 이름은 건드리지 않는다** — `latest-KR.json`이 사라지면 사이트의
  브리핑 화면이 통째로 빈다(웹이 읽는 유일한 브리핑 파일이다).

왜 30일인가: 게이트(§9.1.1)는 **이번 세션 파일 하나만** 본다. 기능상 필요한 건 1일치다.
나머지 29일은 사람 몫 — "어제 뭐가 나갔지"를 파일로 확인할 수 있어야 하고, 발송 사고를
며칠 지나서 들여다볼 수도 있어야 한다. 시장당 하루 1개씩 쌓이므로 상한은 약 60개.

삭제는 `git add data/`가 스테이징하므로(§9.1의 `commit-data.sh`) 별도 처리가 없다.

## 10. 로컬 실행 스크립트

| 파일 | 역할 |
|---|---|
| `start-web.bat` | ASCII 전용 래퍼. `start-web.ps1`을 `powershell -NoProfile -ExecutionPolicy Bypass -File`로 호출 |
| `start-web.ps1` | 포트 5173 점검 → Node 확인 → `web/node_modules/vite` 없으면 `npm install` → `cmd /c npm run dev`를 **숨김 창 백그라운드**로 띄우고 PID를 `.dev-server.pid`에 기록 → 최대 60초 포트 대기 → 브라우저 오픈 → 주소·로그·중지법 안내 |
| `stop-web.bat` / `stop-web.ps1` | PID 파일(프로세스명이 cmd/node인지 검증 후) + 포트 점유 프로세스를 `taskkill /T /F`로 종료, PID 파일 정리, 종료 확인 |
| `sync-data.bat` / `sync-data.ps1` | 로컬 `data/` 정리. 인자 없음(reset) = 로컬 산출물을 stash로 밀고 `git pull --rebase`. `push` = 로컬 산출물을 커밋·푸시(봇과 충돌 시 `-X theirs`로 5회 재시도). `-Quiet` = 무인 모드 |
| `install-sync-task.bat` / `.ps1` | 위를 Windows 예약 작업(`StockPulse-SyncData`)으로 등록. 인자 없음 = 매일 07:10·17:10, `HH:mm` = 하루 한 번, `remove` = 해제 |

`sync-data`가 있는 이유: 파이프라인을 로컬에서 한 번 돌리면 tracked JSON이 190개쯤
한꺼번에 바뀐다. 전부 재생성 산출물이고 봇이 하루 12번쯤 같은 파일을 다시 올리는데,
git은 "수정됨"으로 잡으므로 `git status`가 못 쓰게 되고 그 상태로는 pull/rebase도 막힌다.
버리는 게 기본이되 `git stash`로 밀어 두므로 되돌릴 수는 있다.

**예약 작업으로 자동화** — `install-sync-task.bat`이 `sync-data.ps1 -Quiet`을 하루 두 번
돌리는 작업을 등록한다. 기본 시각 07:10·17:10은 봇의 두 차례 `data-sync`(21:30·07:30 UTC,
런당 26분) 직후다. 그 전에 받으면 헛걸음이다.

무인 실행에서 실제로 위험한 건 **입력 대기**다. 대화형 경로의 `Wait-AndExit`은 키를
기다리는데, 예약 작업에는 키를 누를 사람이 없어서 작업이 끝나지 않은 채 남고 그 다음
실행까지 막는다. `-Quiet`은 이 대기를 건너뛰고 `.sync-data.log`(500줄 유지)에만 남긴다.
같은 이유로 `ExecutionTimeLimit` 30분과 `MultipleInstances IgnoreNew`를 건다.

작업 설정 중 의도가 있는 것:

| 설정 | 이유 |
|---|---|
| `StartWhenAvailable` | PC가 꺼져 있어 시각을 놓치면 켜진 뒤 따라잡는다. 없으면 노트북은 주말마다 건너뛴다 |
| `AllowStartIfOnBatteries` + `DontStopIfGoingOnBatteries` | 전원에 안 꽂힌 노트북에서도 돈다 |
| `LogonType Interactive` | 비밀번호 저장도 관리자 권한도 필요 없고, git 자격 증명을 사용자 것으로 쓴다. 대신 로그온해 있을 때만 실행 |
| `-Hidden` + `-WindowStyle Hidden` | 둘 다 있어야 조용하다. 후자만으로는 창이 깜빡인다 |

같은 스크립트가 `gc.autoPackLimit=8`, `gc.auto=500`을 설정하고 `git gc --auto`를 돌린다.
이 저장소는 190개 JSON을 통째로 다시 커밋해서 로컬 팩이 빨리 쌓이는데 git 기본값
(`autoPackLimit` 50)은 반응이 늦다 — 실측으로 팩 17개·`.git` 106MB까지 갔고, 접고 나니
**16MB**였다. 히스토리가 무거운 게 아니라 안 접혀 있던 것이다.

구현 세부:
- 포트 점검은 소켓 연결이 아니라 `Get-NetTCPConnection -State Listen` — vite가 루프백을 IPv6(`::1`)에만 바인딩하는 경우 `127.0.0.1` 연결로는 놓친다. cmdlet이 없는 환경은 `127.0.0.1`/`::1` 양쪽 소켓 시도로 폴백.
- 로그는 `.dev-server.log`(gitignore), 실패 시 마지막 20줄을 출력.
- 한글 출력은 전부 `.ps1`에 두고 `.bat`은 ASCII만 — 배치 파일에 코드페이지가 섞이면 cmd.exe가 오파싱한다.
- ⚠️ **두 `.ps1`은 UTF-8 BOM으로 저장해야 한다.** Windows PowerShell 5.1은 BOM이 없으면 파일을 ANSI(CP949)로 읽어 한글 리터럴이 파싱 단계에서 깨진다(`濡쒖뺄` 류 증상). `chcp 65001`은 출력 코드페이지만 바꾸므로 해결책이 아니다. 스크립트는 추가로 `chcp 65001` + `[Console]::OutputEncoding = UTF8`을 설정해 콘솔 출력까지 UTF-8로 맞춘다.

| 웹 데이터 없음 | "아직 수집된 데이터가 없습니다" 빈 상태 |

### 실행 시간 — 실측 (2026-07-28)

이 표는 추정이 아니라 `gh run list` 의 실제 duration 을 **잡당 1분 올림**(Actions 과금 단위)
해서 집계한 값이다. 표본: 2026-07-24 ~ 07-28, 완료 런 49개.

| 워크플로 | 런 수 | 합계 | 평균/런 |
|---|---:|---:|---:|
| `data-sync` | 12 | 269분 | **22.4분** |
| `pulse` | 28 | 34분 | 1.2분 |
| `brief-kr` | 3 | 21분 | 7.0분 (전부 `--rebuild` 시절) |
| `brief-us` | 3 | 14분 | 4.7분 (전부 `--rebuild` 시절) |
| `test` | 3 | 3분 | 1.0분 |

개정 후 브리핑 잡은 리허설 dispatch 실측 **37초**(체크아웃 + 게이트 + `pip install` +
`pulse --market US` + 브리핑 생성/렌더 전부 포함) — 즉 과금 1분이다.

정상 운영 시 월 사용량:

```
data-sync : 2회/평일 × 22일 × 22.4분  ≈ 986분   ← 전체의 56%
pulse     : 12회/일  × 30일 × 1.2분   ≈ 432분
brief-kr  : (슬롯 6개 + 발송 1회) × 1분 × 22일 ≈ 154분
brief-us  : (슬롯 8개 + 발송 1회) × 1분 × 22일 ≈ 198분
test      : 푸시 시에만 (paths 필터), 잡당 1분
──────────────────────────────────────────
합계 ≈ 1,770분/월   (무료 2,000분, 여유 ~230분 = 12%)
```

> 개정 전 이 문서는 2,370분/월(한도 초과)로 **추정**하고 `pulse` cron 완화를 1순위
> 완화책으로 적었다. 실측해 보니 `pulse`는 런당 2분이 아니라 1.2분이고 브리핑도
> 3분이 아니라 1분이라, 한도 안에 들어온다. 멀쩡한 기능을 줄일 뻔했다 —
> **완화책을 실행하기 전에 반드시 실측할 것.**

여유가 12%뿐이라 아래는 계속 유효한 안전판이다(필요해지면 효과 순으로):

1. `data-sync`를 하루 1회(미장 마감 후)로 — **−493분**으로 압도적이지만
   국장 마감 데이터가 반나절 늦어진다. 제품 판단이 필요하다.
2. `EVENT_BACKFILL_MAX_PER_TICKER` 하향 → data-sync 자체를 단축 (−100~200분).
3. `pulse` cron을 `0 */4 * * *`로 완화 (−216분).
4. 레포를 public으로 전환하면 Actions 분이 무제한.

수동 dispatch도 같은 지갑에서 나간다. 디버깅으로 `data-sync`를 몇 번 돌리면
(런당 22분) 여유 230분이 금방 사라진다 — 브리핑 경로 확인은 `brief-*` 의
**리허설 모드**(§9.1.2, 런당 1분)를 쓸 것.

## 13. 보안 · 법적 고려

- 시크릿은 env로만 접근(`config.gemini_key()` 등). 코드·데이터·로그에 값이 남지 않는다. `.env`는 `.gitignore`.
- 텔레그램 렌더는 전 필드 `html.escape` — 뉴스 제목의 `<`, `&`가 parse_mode를 깨거나 주입되지 않게.
- 외부 링크는 전부 `target="_blank" rel="noopener noreferrer"`.
- 저작권: 제목·요약 일부 + **원문 링크만** 저장. 본문 전문 저장·재배포 없음. RSS는 배포 목적 피드이므로 HTML 스크래핑을 하지 않는다.
- 규제: 개별 종목 매수/매도 권유·목표가를 생성하지 않는다. LLM 프롬프트에 금지 규칙을 명시하고, 웹·텔레그램 양쪽 하단에 면책 문구를 고정 노출한다.
- 차트 분석(§5.8)의 `actionLabel`은 기술적 분석 교과서의 국면 이름("추격 매수 구간", "눌림목")을 옮긴 것이다. 다음 세 가지를 **항상 함께** 내보내는 것이 이 기능의 전제다.
  1. **근거** — 판정에 쓰인 지표 12가지와 각각의 수치(`signals[]`).
  2. **한계** — `actionNote`·`disclaimer`, 그리고 도움말 "꼭 알아둘 한계" 절.
  3. **출처 구분** — 가격만 본 계산이며 실적·공시는 반영하지 않는다는 사실.

  LLM에도 이 문구를 매매 권유로 고쳐 쓰지 말라고 프롬프트에 못박는다(`llm.brief_summary`).
  목표가·비중·진입 시점은 어느 경로로도 만들지 않는다.
- 사용자 데이터 수집 없음(로그인·분석 스크립트·쿠키 없음). 워치리스트/설정은 브라우저 localStorage에만.

## 14. 알려진 제약 · 문서-코드 드리프트

### 14.1 설계상 제약

- 전 상장종목 커버 불가: KR ETF만 1,150여 개, 개별종목 2,700여 개. 종목당 JSON ~66KB이므로 수천 개는 매 갱신 수백 MB 커밋 + 종목별 뉴스 수집으로 실행 수 시간. → 인기·테마 중심 큐레이션(184종목), 추가는 `config.py` 한 줄.
- 일봉 기준(실시간 시세 없음), 뉴스 매칭은 종목명 문자열 기반이라 동명이의·표기 변형에 취약(별칭으로 보완).
- 휴장일은 2026년 하드코딩(`util/dates.py`의 `HOLIDAYS[시장][연도]`). 해가 바뀌면
  새 목록을 넣어야 한다. 표가 없는 해는 **주말만 거르고 평일은 전부 개장으로 본다** —
  발송을 멈추면 그 해 브리핑이 통째로 사라지므로, 휴장일에 몇 번 더 나가는 쪽을 택했다.
