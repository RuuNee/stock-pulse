## B1. 게이트가 "스키마가 낡은 것"을 못 본다 ⭐ 우선

**증상**
차트 분석에 `trendlines`·`levels.high52Pct` 등을 추가했는데, 국장 데이터가 이미
그날 날짜로 최신이라 `data-sync` 가 건너뛰었다. 새 필드가 안 들어와서 화면에서
추세선 버튼을 눌러도 아무것도 안 그려졌고, 수동 dispatch 로 강제 재빌드해야 했다
(2026-08-04).

**원인**
`gate.data_stale()` 이 **날짜만** 본다. `index.json` 의 `date` 가 마지막 마감
세션과 같으면 최신으로 판정한다. 스키마가 바뀐 것은 볼 방법이 없다.

```python
# pipeline/gate.py
have = max(dates)
if have >= session.isoformat():
    return False, f"{market}: 이미 {have} 까지 있음 — 건너뜁니다"
```

필드를 추가할 때마다 같은 일이 난다. 그때마다 사람이 알아채고 수동 dispatch 를
해야 하는데, 안 하면 **조용히** 낡은 스키마로 남는다.

**고치는 법**
`analysis` 에 스키마 버전을 싣고 게이트가 같이 본다.

1. `pipeline/config.py` 에 `TA_SCHEMA_VERSION = 2` 추가 (필드를 바꿀 때마다 올린다)
2. `analyze/technical.py::analyze()` 반환 dict 에 `"v": TA_SCHEMA_VERSION`
3. `build/site_data.py::_index_entry()` 의 `analysis` 압축본에도 `"v"` 포함
4. `gate.data_stale()` 이 날짜와 버전을 **둘 다** 본다 —
   `date` 가 최신이어도 `v` 가 `TA_SCHEMA_VERSION` 보다 낮으면 stale

**검증**
- `tests/test_sync_gate.py` 에 케이스 추가: 날짜는 최신인데 `v` 가 낮으면 `True`
- 버전 필드가 아예 없는 구데이터(= v1)도 stale 로 잡히는지
- 반대로 날짜·버전 둘 다 최신이면 여전히 건너뛰는지 (헛돌면 26분이 날아간다)

**주의**
버전을 올리면 **전 종목이 한 번에 재빌드**된다. 국장 18분 + 미장 25분이라
슬롯 하나가 43분짜리가 될 수 있다. `tests/test_sync_schedule.py` 의 마감선
검사가 그때도 통과하는지 확인할 것.

**건드릴 파일**
`pipeline/config.py` · `pipeline/analyze/technical.py` · `pipeline/build/site_data.py`
· `pipeline/gate.py` · `tests/test_sync_gate.py` · `md파일/02-데이터스키마.md`

## B2. `0183J0` (TIGER 미국우주테크) 일봉이 0건

**증상**
`data/tickers/KR/0183J0.json` 의 `ohlcv.rows` 가 빈 배열이다. 그래서
`analysis` 가 `null` 이고, 291종목 중 이 하나만 차트 분석이 없다.
차트도 안 그려진다.

**원인 (미확인)**
시세(`quote.close = 6785`)와 시가총액은 정상으로 들어온다. **일봉 히스토리만**
안 온다. 차트 분석 도입 **전부터** 그랬다 — `git show f9afab8:data/tickers/KR/0183J0.json`
에서도 `rows` 가 0건이다. 즉 이번에 만든 버그가 아니라 수집 단계 문제다.

신규 상장 ETF 라 `FinanceDataReader` 가 아직 일봉을 안 주는 것으로 보이지만
확인하지 않았다.

**고치는 법 — 셋 중 하나**
1. **원인부터 확인**: `fdr.DataReader('0183J0', '2026-01-01')` 을 직접 돌려
   빈 프레임인지, 예외인지, 다른 심볼 표기가 필요한지 본다.
2. 소스 문제면 **유니버스에서 뺀다** (`config.KR_ETF`). 화면에 빈 종목이
   있는 것보다 없는 게 낫다.
3. 대체 소스가 있으면 그쪽으로 폴백 (`collect/prices.py::fetch_ohlcv`).

**검증**
- `python -m pipeline.run doctor` 로 소스 상태 확인
- 빼기로 했다면 `all_universe()` 개수가 291 → 290 인지, `index.json` 에서
  사라지는지

**주의**
같은 증상이 다른 신규 상장 종목에서도 날 수 있다. 원인을 확인하면 "일봉 0건이면
유니버스에서 자동 제외 + 경고" 같은 일반 처리를 넣을지도 같이 판단할 것.

**건드릴 파일**
`pipeline/config.py`(KR_ETF) 또는 `pipeline/collect/prices.py` · `pipeline/doctor.py`

## B3. 미장 169종목 첫 실행 시간 실측 (확인만)

**할 일**
2026-08-04 에 미장 유니버스를 62 → 169 로 늘렸다. 실행 시간을 **추정치
25분**으로 잡았을 뿐 재보지 않았다.

첫 미장 슬롯(20:15 UTC) 실행 후:
```bash
gh run list --workflow=data-sync.yml --limit 5
```
로 실제 소요를 확인한다.

- 35분을 넘으면 `tests/test_sync_schedule.py` 의 `RUN_MIN["US"]` 를 올리고
  마감선 검사가 여전히 통과하는지 본다. 안 통과하면 슬롯을 앞당긴다.
- Actions 사용량도 같이 본다 (`Settings → Billing`). 예상 월 ~1,280분 /
  무료 2,000분.
