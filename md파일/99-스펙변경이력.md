## 2026-07-23 — v0.2.0 ⭐ 이벤트 뉴스 히스토리 백필

### 배경
첫 실전 데이터 확인 결과, 몇 달 전 급등락일(예: 삼성전자 -12.3%)에는 매칭된
뉴스가 없어 "뚜렷한 개별 뉴스를 찾지 못했습니다"만 표시됨. 우리가 수집하는
RSS는 최근 뉴스만 담기 때문. R5(차트-뉴스 연동)의 핵심 가치가 최근 이벤트에만
작동하는 한계.

### 변경
- **날짜 지정 Google News 백필 추가** — Google News RSS의 `after:/before:`
  연산자로 특정 과거 날짜의 뉴스를 가져와, 뉴스가 없는 이벤트에 붙임.
  국장은 `"종목명" after:.. before:..`, 미장은 `"CompanyEn" stock after:.. before:..`.
  실측: 삼성전자 2026-06-23(-12.3%)에 "삼성전자 주가, 오늘 왜 급락했을까?" 매칭됨.
- **비용 제한** — 종목당 최대 6개(고심각도·뉴스없음 우선), 200일 이내 이벤트만.
  60종목 × 6 × 1.2s ≈ 7분 추가. `EVENT_NEWS_BACKFILL` 플래그로 on/off.
- **초보모드 이벤트 필터 개선** — severity≥2 뿐 아니라 "뉴스가 매칭된 이벤트"도
  노출. 최근의 설명 가능한 이벤트가 숨겨지던 문제 해결 (web).
- **NewsCard 중첩 앵커 버그 수정** — 카드 루트를 `<a>`→`<div>`로 변경.
  종목 칩 링크가 앵커 안에 중첩되어 hydration 오류 발생하던 문제 (web).

## 2026-07-28 — 브리핑 발송 시각을 "개장 30분 전"으로 재설계

### 문제 — GitHub 스케줄러 지연
사용자 요구는 "장 시작 전 전송"인데(2026-07-22 요구사항), 미장 브리핑이 개장 후에 도착했다.
원인은 **cron 시각 자체가 아니라 GitHub 스케줄러가 예약 시각을 안 지키는 것**이다. 실측:

| 워크플로 | 예약 | 실제 run 생성 | 지연 |
|---|---|---|---|
| brief-kr (2026-07-26) | 22:30 UTC | 23:27:24Z | **+57분** |
| brief-us (2026-07-27) | 12:30 UTC | 15:23:02Z | **+173분** |

`run_started_at == created_at`이므로 concurrency 큐 대기가 아니라 스케줄러 자체의 지연이다.
GitHub은 정각·30분에 스케줄이 몰릴 때 예약 실행을 밀거나 아예 드랍한다(문서화된 동작).
brief-us는 7/27이 워크플로 생성 후 첫 평일 슬롯이었는데 173분 밀려 **개장 2시간 뒤**인
00:34 KST에 발송됐다.

부차 원인 하나 더: 기존 시각 계산에 **job 실행 시간이 빠져 있었다.** `--rebuild` 탓에
실제 소요가 11~19분(brief-us 11m24s, brief-kr 18m45s 실측)이라, cron이 정시에 떠도
메시지는 그만큼 뒤에 나간다.

### 변경 — 다중 슬롯 + 시각 게이트
단일 cron으로는 도착 시각을 보장할 수 없으므로 구조를 바꿨다.

1. **슬롯 다중화** — 하나가 밀려도 다음 슬롯이 제시간에 뜰 확률을 남긴다.
   - `brief-kr`: `11 23 * * 0-4`, `23 23 * * 0-4` (08:11 / 08:23 KST 시작)
   - `brief-us`: `41 12`, `53 12`, `41 13`, `53 13` `* * 1-5` (08:41 / 08:53 ET 시작)
   - 슬롯 = 목표 도착시각 − 빌드 시간. 정각·30분은 피했다.
2. **발송 창 게이트** — 실제 로컬 시각이 창 밖이면 체크아웃 전에 즉시 종료.
   KR `08:05~08:35 KST`, US `08:35~09:05 ET`. → 늦게 뜬 실행이 개장 후 브리핑을 쏘지 않는다.
3. **중복 발송 게이트** — `data/brief/{세션일자}-{시장}.json`이 이미 있으면 종료.
   슬롯끼리는 같은 concurrency 그룹이라 병렬로 겹치지 않으므로, 먼저 성공한 슬롯의
   커밋을 뒤 슬롯이 체크아웃해서 보게 된다.
4. **미장 서머타임** — cron은 UTC 고정이라 DST를 못 따라간다. EDT/EST 양쪽 슬롯을 모두
   예약하고 계절이 어긋난 쪽은 창 게이트가 걸러낸다(07:41 ET 또는 09:41 ET로 뜬다).
5. **푸시 재시도** — 커밋 스텝을 pulse와 동일하게 `git pull --rebase --autostash` 3회
   재시도로 통일(봇 커밋 경합 대비).

## 2026-07-28 — v0.5.0 ⭐ 스케줄러 지연에 견디는 브리핑 발송

### 증상 (사용자 신고 3건)
1. 금일 장 시작 30분 전 텔레그램 브리핑이 **안 옴**
2. 웹 브리핑도 **월요일에서 멈춤**
3. 다른 뉴스 수집은 정상인지 확인 필요

### 원인
코드 버그가 아니다. **슬롯 배치 문제.** `gh run list` 실측:

```
brief-kr  23:11 UTC 예약 → 00:09:40Z 시작 (+58분) → 09:09 KST → 발송 창 밖, 차단
brief-kr  23:23 UTC 예약 → 00:14:22Z 시작 (+51분) → 09:14 KST → 발송 창 밖, 차단
```

발송 창 게이트는 **설계대로** 동작해 개장(09:00) 후 발송을 막았다. 문제는 슬롯이
2개뿐이라 둘 다 밀리면 그날은 아예 발송이 없었다는 것. 이 저장소의 스케줄러 지연은
`+6 ~ +202분`으로 널뛴다(pulse +114, brief-us +173, data-sync +202 실측).
옛 배치는 0~240분 지연 중 **30개 구간(12%)만** 커버했다.

②는 ①의 결과다. Vercel 배포와 `cache: "no-cache"` fetch 모두 정상이었고,
브리핑 JSON 이 생성되지 않아 웹이 옛 파일을 계속 그린 것뿐이다.

③은 정상이었다. `doctor` 결과 매크로 12/12, RSS 19 정상 / 1 죽음(`yna_market`).

### 변경
- **`pipeline/gate.py` 신설** — 발송 판정(수동 강제 → 휴장일 → 중복 → 발송 창)을
  셸에서 파이썬으로. `python -m pipeline.run gate --market KR`. `pip install` 전에
  돌아야 하므로 **표준 라이브러리만** 쓴다.
- **`config.BRIEF_WINDOW`** — 발송 창을 설정화. 개장 75분 전 ~ 20분 전
  (KR `07:45~08:40 KST`, US `08:15~09:10 ET`). 기존 30분 → 55분.
- **슬롯 재배치** — KR 2 → **7개**(19:20~23:20 UTC), US 4 → **9개**(08:40~14:00 UTC),
  둘 다 40분 간격. 슬롯 간격(40분) < 발송 창(55분)이라 지연 0~240분 전 구간이 덮인다.
- **발송 경로에서 `--rebuild` 제거** — `pulse --market X` → `brief --send`.
  잡이 11~19분 → **37초**(실측). 슬롯을 3.5배로 늘렸는데도 사용 분은 줄었다.
- **브리핑 concurrency 분리**(`stock-pulse-brief-KR|US`) — 26분짜리 `data-sync` 뒤에
  큐잉되면 발송 창을 통째로 놓칠 수 있었다.
- **스케줄 잡 전부 `checkout ref: main`** — 스케줄 트리거는 예약 시점 SHA 를 준다.
- **`.github/scripts/commit-data.sh`** — 네 워크플로의 커밋·푸시 통일. 거절 시
  `rebase -X theirs` 후 재시도(5회). 기존 `pull --rebase`는 충돌 시 데이터를 날렸다.
- **발송 실패 시 exit 1** — 브리핑 파일이 커밋되지 않아 남은 슬롯이 자동 재시도한다.
- **리허설 모드** — `workflow_dispatch` 입력 `send=false`면 발송도 커밋도 하지 않고
  빌드·렌더링만 확인한다. 텔레그램을 건드리지 않고 경로를 점검할 수 있다.
- **죽은 피드 `yna_market` 제거** — 피드 20종 → 19종(KR 9 + US 10).

  `data/` 로 판정하는데 발송·커밋은 Actions 에서 일어난다. pull 안 했으면 이미 나간
  브리핑도 "없음"으로 보인다. 네트워크는 타지 않고 마지막 fetch 기준이라 그 fetch
  시점도 같이 찍는다.
- **CLI 출력을 UTF-8 로 고정**(`run.py` `_force_utf8_output`). 윈도우 기본 cp949 가
  `—` 를 못 담아, 결과를 파일·파이프로 넘기는 순간 `UnicodeEncodeError` 로 죽었다.

- **`UpdateTip`** — 갱신 주기를 화면에서 바로 확인. "뉴스도 차트도 실시간이겠지"라는
  오해가 실제로 나왔다. 셋 다 주기가 다르고 실시간인 건 하나도 없다: 뉴스·지수는
  2시간마다(pulse), 종목 가격·차트는 평일 하루 2번(data-sync), 브리핑은 거래일 1번.
  차트가 일봉이라는 점도 같이 적었다 — 장중에 오늘 봉이 없는 이유다. 홈 하단
  "마지막 갱신" 옆과 종목 차트 아래에 둔다.
